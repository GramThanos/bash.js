Getting Started

bash.js is one file. Load it whichever way your environment expects.

Browser

<script src="bash.js"></script>
<!-- window.BashJS is now available -->

Node / CommonJS

const BashJS = require('./bash.js');

ESM

import BashJS from './bash.js';

Quick Start

Supply the host callbacks, then run a command line. This example maps them onto the real disk with Node's fs:

const fs = require('fs');
const path = require('path');

const callbacks = {
  read: async (p) => {
    try { return fs.readFileSync(p, 'utf8'); }
    catch (e) { if (e.code === 'ENOENT') return null; throw e; }
  },
  write: async (p, content, opts) => {
    if (opts?.type === 'dir') { fs.mkdirSync(p, { recursive: true }); return; }
    fs.mkdirSync(path.dirname(p), { recursive: true });
    fs.writeFileSync(p, content, { flag: opts?.append ? 'a' : 'w' });
  },
  delete: async (p, opts) => fs.rmSync(p, { recursive: !!opts?.recursive, force: true }),
  move: async (src, dst) => fs.renameSync(src, dst),
  stdout: (chunk) => process.stdout.write(chunk),
  stderr: (chunk) => process.stderr.write(chunk),
};

const result = await BashJS.exec(
  'grep -rn TODO src | sort | head -5 > todo.txt',
  '/home/user/project',
  callbacks,
  { env: { HOME: '/home/user' } }
);

result.exitCode; // 0
result.stdout;   // captured output
result.cwd;      // final working directory

TIP

For tests and demos, BashJS.memfs(tree) gives you an in-memory filesystem that already implements the callback contract. The playground above uses it.

Persistent Session

State (cwd, environment, functions, $?, open file descriptors) survives between calls:

const sh = BashJS.create({
  cwd: '/',
  ...BashJS.memfs(),
  stdout: (c) => console.log(c),
  stderr: (c) => console.error(c),
  env: { PATH: '/usr/bin:/bin' }
});

await sh.exec('cd /tmp && export X=1');
await sh.exec('echo $X; pwd');   // "1\n/tmp\n"

sh.getCwd();        // '/tmp'
sh.getEnv();        // { X: '1', PATH: ..., PWD: '/tmp', ... }
sh.setEnv('K', 'v');

API

BashJS.exec(command, cwd, callbacks, options?)

Runs a single command string. Returns Promise<{ exitCode, stdout, stderr, cwd, env }>.

BashJS.create(options)

Creates a persistent session with exec(), getCwd(), getEnv() and setEnv().

const sh = BashJS.create({
  cwd: '/',                    // initial working directory
  read, write, delete, move,   // required FS callbacks
  stdout, stderr,              // required stream callbacks
  env: {},                     // initial environment
  now: () => new Date(),       // clock for `date`
  timezone: 'UTC',             // timezone for `date`
  maxLoopIterations: 100000,   // safety guard on loops
  maxOutputBytes: 16 * 1024 * 1024,
  maxCallDepth: 200,           // function/subshell recursion guard
  signal: abortSignal,         // AbortSignal to cancel execution
  strict: false                // throw on unsupported syntax
});

BashJS.registerCommand(name, handler)

Adds a custom utility. The handler receives a command context and returns an exit code.

BashJS.registerCommand('hello', async (ctx) => {
  ctx.stdout.write('hi\n');
  return 0;
});

Other helpers

  • BashJS.parse(command) returns the AST, for tooling and debugging.
  • BashJS.commands() lists every command name: builtins, utilities and custom commands.
  • BashJS.memfs(initialTree?) returns an in-memory filesystem adapter.
  • BashJS.version is the library version string.

Host Callbacks

Callbacks may be sync or return a Promise. Paths are always absolute, normalized POSIX paths.

CallbackSignatureSemantics
readread(path) → FileNode | nullReturn null (or throw ENOENT) when missing.
writewrite(path, content, { append?, type? })type: 'dir' creates a directory. append: true appends, otherwise truncates.
deletedelete(path, { recursive? })Remove a file or directory.
movemove(src, dst)Rename or move; dst is the final full path.
stdoutstdout(chunk)Receives top-level fd 1 output in order.
stderrstderr(chunk)Receives top-level fd 2 output in order.

A FileNode can be any of these shapes:

'file contents'                          // string: regular file
['a.txt', 'sub']                         // array of names: directory
[{ name: 'a.txt', type: 'file' }, ...]   // directory with typed entries
{ type: 'file', content: '...', size?, mtime?, mode? }
{ type: 'dir',  entries: [...],  mtime?, mode? }

Optional stat(path) and exists(path) callbacks are used for speed when supplied.

Bash Features

  • Execution: pipelines (|, |&), lists (; & && ||), subshells, groups, functions with local/return.
  • Control flow: if/elif/else, for, while/until, case, (( )), [[ ]] with =~ and file tests.
  • Redirections: > >> < <> &> n>&m n>&-, here-docs, here-strings, <(cmd) / >(cmd), /dev/null and /dev/fd/N.
  • Expansions: brace {a,b} {1..10..2}, tilde, parameter (${v:-d} ${v//p/r} ${#v} arrays, indirection), command, arithmetic, word splitting, globbing incl. **.
  • Options: set -e -u -x -o pipefail -o noclobber, shopt.
  • Builtins: cd echo printf pwd true false : exit return export unset readonly local declare set shopt shift read test [ eval source exec command type which hash basename.

Design Decisions

  • Async everywhere: callbacks may hit IndexedDB or a remote FS, so exec returns a Promise.
  • Buffered pipelines: simple and deterministic; inputs are finite.
  • Text-only data: UTF-8 strings; byte-oriented flags use TextEncoder offsets.
  • GNU is the reference for options and messages, with a C/POSIX locale.
  • Background jobs (&) run synchronously.
